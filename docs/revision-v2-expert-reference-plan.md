# Supplemental expert-reference check

This extension was specified after the nine PressButton primary and second-GPU
policy cohorts had been observed, and before any corresponding expert-reference
test cohort was run. It is not part of the original pre-test learning plan.

Run the unchanged privileged reference controller on all 30 ordered primary
reset IDs of every core task, at the same control horizon and with the frozen
open asset profile. Retain every outcome. This measures the reference
controller's performance on the exact cohort used by the learned policies.
Reference failure is not evidence that a state is physically infeasible.

No resulting demonstration enters training or validation. No task, controller,
policy, checkpoint or test denominator changes in response. A later conditional
description of reference-successful resets must retain the unconditional primary
score and cannot replace it. Controller execution is distinct from the already
declared paired action-recording replay gates.

PressButton, PushSlider and PullLever use the frozen expert rollout mode and
physical trace replay. Valve, Hatch and Shell use the frozen collection backend
to preserve the original controller exactly; their RGB is archived losslessly
after all 30 outcomes are audited. Initial measured states are compared with the
primary cohort wherever the stored schemas permit it. A mismatch is retained and
prevents claiming an exactly paired initial state.

The first PressButton check can run alongside training. The remaining five jobs
wait until the primary campaign and queued clean-checkout inference have finished,
avoiding concurrent large simulations and a second active training dataset.
Outputs live outside the primary training data and remain explicitly labeled
supplemental references. All six tasks are retained regardless of the outcomes.
